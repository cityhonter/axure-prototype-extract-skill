# 需求文档模板与撰写规则

> 本文件是 `axure-prototype-extract` skill 的文档模板。撰写阶段必须按此模板产出，因为
> `check_coverage.cjs` 会机器校验其中的标注格式——格式不合规会导致校验失败。

## 一、README.md（总览）模板

````markdown
# <模块名> · 原型需求提取总览

> 提取来源：Axure 原型 `<原型URL>`
> 提取日期：<日期>
> 范围说明：<哪些页面被排除及原因；无排除则写"全量覆盖">

## 1. 模块定位
<业务背景一两句；涉及的端（监管端/企业端/移动端…）与角色，用表格列出：端 | 使用者 | 菜单路径 | 页面>

## 2. 页面索引与截图
| # | 端 | 页面 | 需求文档 | 截图 |
（每页一行，文档与截图均为相对链接）

### 交互/弹窗截图
（按页面分组的交互截图链接表，见 截图-交互/）

## 3. 通用 UI 规范
<从多个页面归纳的共性：页面骨架、统计卡片联动、筛选区、表格、状态 tag 配色、分页、弹窗形态、附件上传限制、字数限制等>

## 4. 全局业务规则
<跨页面重复出现的公式/状态机/审核流，逐条编号（§4.1、§4.2…），引用标注原文。
同一规则不要在多个页面文档里各写一遍，页面文档只引用章节号。>

## 5. 术语表
<业务名词及依据原型上下文的解释>

## 6. 原型疑点 / 建议与产品确认
<所有互相矛盾的标注、疑似复制残留、必填性不一致等。只记录不裁决。
典型模式：同一规则两种表述 / 标注内容与所在页面业务无关 / 表单必填符号与标注冲突 />

## 7. 附件目录
<截图/、截图-交互/、数据/ 的说明>
````

## 二、页面文档（`NN-端-页面名.md`）模板

````markdown
# NN · <端> — <页面名>

> 菜单路径：<Sitemap 路径>
> 截图：[./截图/NN-xxx.png](./截图/NN-xxx.png)（黄色角标 = 下方标注编号）

![<页面名>](./截图/NN-xxx.png)

## 页面结构
<按视觉顺序编号列出：Tab、统计卡片区（逐项列出卡名）、填报/功能说明（红字原文）、筛选区（逐项列出字段与类型）、表格、操作按钮、弹窗/面板>

## 表格列
| 列 | 说明（标注原文） |
（每列一行；说明列必须写标注出处或"—"；蓝色链接列要注明点击行为）

### 操作列状态规则（如适用）
| 审核状态 | 操作按钮 |
（从可见控件文字的操作列样本行归纳，逐状态列出）

## <新增/编辑等>弹窗（label=xxx，原型隐藏面板提取）
<逐字段列出：字段名（必填带*）| 控件类型 | 字数限制 | 校验规则/数据来源（引标注原文）>
<按钮：保存/暂存/返回；确认提示原文>

## 统计卡交互（如适用）
<标注原文：每张卡点击后联动哪个筛选条件>

## 需求标注原文（编号对应截图黄标）
| <fn> | 标注内容 |
（⚠️ 每条标注独占一行！禁止 `| 2 / 3 / 6 |` 这种合并写法，check_coverage 按行核对。
   与本页业务无关的疑似残留标注也要保留，注明"疑似模板残留，见 README §6"。
   已汇总进 README 全局规则的标注，此行可写"同 README §4.x"但仍必须占一行。）

## 交互/弹窗截图
- [名称](./截图-交互/NN-xxx.png)（一句话说明内容）
<无交互截图的页面写明原因，如"行链接为页面跳转，原型未包含详情页">

## 给开发的提示
<从原型可推断的实现要点：数据源、计算字段、联动关系；不要臆造原型之外的需求>
````

## 三、撰写规则（保证稳定与零遗留）

1. **标注原文一字不改**：标注是需求的唯一权威来源。转写时保留编号、标点、步骤序号；
   HTML 转文本产生的换行用 `/` 或 `；` 连接。
2. **可见+隐藏全都要**：digest 的"可见控件文字"用于还原页面结构；
   "隐藏控件文字"用于撰写弹窗明细——每个隐藏面板（Axure label 如 基本信息/详情/日志/新增）
   单独成章，字段逐个列出，不允许只写一句"含新增弹窗"。
3. **零控件页（说明页）**：`widgetCount=0` 的页面是说明页，截图里的红字就是需求原文，
   必须逐字转写到文档，并描述参考截图里的布局。
4. **矛盾不裁决**：发现表述冲突时两处都保留，写入 README §6 疑点清单。
5. **统计卡/筛选/表格列名以 digest 可见控件文字为准**，按 x,y 坐标还原行列顺序；
   同名文案出现在多处时（如"企业名称"既是筛选项又是列名），按坐标区分归属。
6. **写完即自检**：运行 `node check_coverage.cjs <输出目录>`，必须全绿后才算完成；
   校验失败按报告逐项补齐（缺标注行→补表格行；缺弹窗内容→补弹窗明细；缺截图→重截）。
